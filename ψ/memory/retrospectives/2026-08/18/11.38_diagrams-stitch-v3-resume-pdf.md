**Friction point 3 — WeasyPrint's first PDF pass shipped with broken Thai glyphs** because I didn't check font coverage before rendering — `fc-list` showed no Thai-capable font installed, and the default sans-serif fallback silently mangled "ปวช." into garbage characters. Caught it via text extraction before calling the task done, but it should have been a pre-check, not a post-hoc catch.

## Lessons Learned

- **When a source document is claimed to exist "somewhere," check the current repo's own subfolders (`docs/`, project root) before searching external drives** — the actual source is more often already checked-in and just unindexed in memory than it is scattered externally.
- **Before reaching for a browser-dependent tool (Puppeteer, Playwright, headless Chrome) in a sandboxed environment, check for a non-browser alternative first** (a hosted rendering API, a native library with system deps already present) — sandboxes without sudo access to install Chromium's shared libraries are common enough that this should be the default assumption, not the fallback after a failure.
- **When rendering user-facing documents with non-Latin script content, check font glyph coverage (`fc-list`) before rendering, not after** — a missing font doesn't error, it silently substitutes broken glyphs, which is much easier to miss without an explicit text-extraction check.
- **A "we checked X and it wasn't there" search that only covers 1-2 obvious locations isn't exhaustive enough to base a content-truthfulness decision on** — when a factual claim about someone's real skills/experience is being dropped for "no evidence found," the search should extend to any canonical documents (resume, existing docs folder) before asking the user to confirm the removal.
