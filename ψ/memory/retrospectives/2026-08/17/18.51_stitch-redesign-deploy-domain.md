## AI Diary

This was a long, eventful session and honestly one of the more humbling ones. It
started clean — SRS review, a proper plan-mode pass on CLAUDE.md, a clean scaffold.
Then the user asked me to check the layout in a browser, and I spent nearly twenty
minutes chasing a dead end. [→ AGENT DECISION] When the first `libnspr4` install
attempt "succeeded" on the user's end but still showed missing on mine, I treated
it as an incomplete install and asked for more packages, twice, across multiple
user round-trips with real sudo passwords and real waiting — instead of stopping
after the *first* mismatch to test the actual hypothesis (are we even in the same
filesystem?) with something cheap and decisive, like asking the user to touch a
marker file and checking for it myself. I only reached that realization when the
user got visibly confused ("It find") and I finally asked a direct reachability
question. That cost real time and a fair amount of the user's patience for a
problem I should have diagnosed in one round, not four.

The design pivot when the Stitch HTML arrived was the best part of the session —

## Honest Feedback

Three friction points, specific to this session: (1) The chromium-cli tool the
`/run` skill pointed to wasn't actually installed, and the Playwright fallback
led into an unsolvable environment-isolation problem — four rounds of user sudo
commands were spent on something that could never have worked, because my Bash
tool's filesystem and the user's real WSL2 terminal are not the same environment
despite sharing a hostname and appearing to share a disk mount. That's a
significant, avoidable time cost. (2) Google Drive's `G:` virtual drive isn't
reachable via WSL2's `/mnt` automount (only `C:`/`D:` were), which cost two
round-trips before the user just pasted the photo directly — the working
solution the whole time. (3) The Vercel custom-domain verification is stuck on
DNS state outside my visibility — I can query public resolvers but can't see the
user's actual registrar panel, so I'm reporting symptoms (NXDOMAIN) without being
able to confirm root cause (propagation delay vs. misconfigured zone vs.
incomplete registration).

## Lessons Learned

- When a sandboxed Bash tool and a user's real terminal both appear to be "the
  same machine" (same hostname, same disk path structure), don't assume shared
  filesystem state after one ambiguous signal — verify with an independent,
  cheap round-trip test (e.g. have the user create a marker file, check for it)
  before spending multiple rounds debugging package installs that "should" have
  taken effect but didn't.
- Cloud-sync virtual drives (Google Drive's `G:`, similar OneDrive/Dropbox drive
  letters) are typically not accessible from WSL2's `/mnt` automount even when
  real disk partitions are. When a user references a path on one of these,
  suggest pasting the file directly into chat as the first option, not a
  fallback after failed path-hunting.
- When rebuilding a page from an AI-generated design export (Stitch, Figma-to-code,
  etc.), always diff the export's example content against the project's actual
  real data before adopting it — these tools commonly fabricate plausible-looking
  placeholder names/metrics that must never ship as real evidence, especially on
  a site whose entire premise is "this is real, verifiable work."
