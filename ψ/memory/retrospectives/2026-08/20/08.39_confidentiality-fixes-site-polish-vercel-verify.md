## Lessons Learned

- **Verify a stated premise about file/document state before treating it as true, even
  when a human states it with confidence.** Benz's plan said the resume already had the
  corrected Lumine narrative — it didn't. If I'd trusted that and only fixed the site,
  the exact confidential numbers would have stayed one click away via the live resume
  download. When a premise is load-bearing for a scope decision, read the actual file
  before acting on it.
- **In sandboxed dev environments, don't assume tooling built in a prior session
  persists to the next one.** Extracted binaries, patched system libs, and installed
  fonts vanish between sessions here. Prefer approaches that are cheap to fully rebuild
  (pip venvs, downloaded font files over system font installs) or that hand a step to a
  human with the right native tooling, rather than re-fighting the same
  no-sudo/no-browser constraint session after session.
- **A confidentiality/IP scope given by the user is a starting point, not a ceiling** —
  when asked to fix "3 named diagrams," a full grep of the actual source surfaced 8, plus
  an entirely separate exposure vector (the resume PDF) the user didn't know was still
  broken. Complete the actual exposure surface, not just the literally-named instances,
  and say so explicitly rather than silently expanding scope.
